# Security Policy

## Supported versions

Security-sensitive corrections are made on `main` and included in the next tagged release. Consumers should use the latest release and review updates because the project remains pre-1.0.

## Reporting a vulnerability

Use this repository's GitHub **Report a vulnerability** form to submit a private security advisory. Do not open a public issue for a vulnerability that could expose users, credentials, private data, or repository integrity.

A useful report identifies the affected document or workflow, realistic impact, reproduction or misuse path, affected versions, and a safe remediation idea when available. Do not include working credentials, unnecessary personal data, or confidential production logs.

Security-relevant issues include dangerous commands presented as safe, mutable content presented as immutable, instructions that could disclose secrets, supply-chain weaknesses in repository automation, and authorization guidance that could trigger unintended external actions.

General disagreements about best practices, unsupported integrations, and ordinary documentation errors may use public issues.

No response time, embargo period, audit status, or security warranty is promised.
